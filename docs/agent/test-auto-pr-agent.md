# 테스트·PR 에이전트

테스트 수와 도메인은 현재 구현된 기능을 기준으로 정한다.

## 작업 순서

1. 변경된 기능의 입력, 출력, 오류와 외부 의존성을 소스에서 찾는다.
2. 성공·실패·경계 조건 가운데 행동을 검증할 사례를 선택한다.
3. 현재 테스트 타깃의 Swift Testing 스타일에 맞춰 독립적인 테스트를 작성한다.
4. 관련 테스트를 실행하고 실패 원인을 구현·테스트·환경으로 구분한다.
5. 검증 결과와 미검증 범위를 PR에 적는다.

테스트 이름이나 커버리지 수치를 임의로 채우지 않는다. 승인·머지·이슈 종료는 실제 GitHub 상태를 확인하고 보고한다.
